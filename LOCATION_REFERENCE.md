# Postal reference and service-jurisdiction review

New intake uses a minimal factual extract from the publicly downloaded [USPS ZIP Locale Detail workbook](https://postalpro.usps.com/ZIP_Locale_Detail), October 2026 file. `data/usps_zip_facilities_2026_10.json` contains 37,103 recognized delivery ZIPs and the physical states of their associated postal facilities. The original workbook URL, month and SHA-256 digest are embedded in the extract. It contains no facility street addresses, customer data or credentials.

**This is not an authoritative ZIP-to-property-state mapping.** A postal facility can be located across a state boundary. For example, the source associates delivery ZIPs 56520 and 56721 with facilities in both Minnesota and North Dakota. The source must never determine contractor licensing jurisdiction or silently reclassify an existing record. No invented prefix/exception table is used.

If the submitted state lacks a facility association for the ZIP, or the ZIP is not in this snapshot, the request is saved as `Needs location review`. Unknown codes are not described as definitively invalid: a valid postal code may be absent from this operational file. The request cannot match, be accepted or enter new checkout while held. The consumer can track or cancel it. Recognized associations remain a plausibility signal, not verification of a street address or actual property jurisdiction.

Administrators review an individual held request at `/admin/leads/<id>/location`, independently confirm property jurisdiction and record evidence and private notes. Approval releases it only into an enabled state. If service is unavailable, the request is cancelled with a generic consumer email, retaining the original record. Each new review retains the previous and confirmed state; older unknown source states are left unfilled. A unique review and conditional state update prevent duplicate decisions; PostgreSQL uses the shared lead lock. Review, state scope, pending-offer cancellation and any cancellation email share a transaction. Private evidence does not enter consumer emails or status pages.

The original intake brand is retained separately from the confirmed state. A consumer who submitted on the Minnesota website continues receiving Minnesota tracking links even if the property state is corrected. Existing records default to their original Minnesota intake brand. Only the fixed approved website origins appear in emails.

Refresh the snapshot through a reviewed source update when USPS publishes a new file. Verify headers `DELIVERY ZIPCODE` and `PHYSICAL STATE`, preserve leading zeros, combine all associated facility states, retain source URL/month/hash, and test the cross-border examples before changing the pinned version in `location_review.py`. Retain only ZIP/state facts, not facility addresses. No runtime scraper or unreviewed automatic geographic reclassification is enabled.

For complete postal city/state validation, obtain authorized access to the [USPS City State Product](https://postalpro.usps.com/address-quality/city-state-product) or an appropriate USPS address API. For actual property jurisdiction, use address-level verification or documented manual evidence. [Census guidance](https://www.census.gov/programs-surveys/geography/guidance/geo-areas/usps_census_city.html) explains why postal names and geographic location differ. This reference guard does not replace those sources or license/insurance review.
